# Tipax Shipping — Odoo 18 sandbox
Independent stock_delivery connector inspired by DHL carrier hooks. No mobile_service dependency. Create one company-specific shipping method per office; provider Tipax, test environment, integration level rate. Enter Bearer credential in administrator settings, confirm currency and multiplier, configure both callback URLs (owned test endpoint). No secret shipped. Test Connection calls Cities. On incoming/outgoing transfer choose carrier, open Tipax tab, select direction, address, city ID, parcel details, declared value and payment/service IDs. Get Tipax Price then Register explicitly. Stock validation never creates a shipment. Standard sale quotation rating intentionally returns an explanatory error. One parcel per transfer. For resend create a new transfer only if a real inventory movement is required; otherwise this version cannot represent a second parcel on the same transfer. Link previous transfer. Cancellation is a request only, status 30 only, verify tracking. Tracking cron disabled until configured; enable in scheduled actions. Internal label and handover are not official Tipax operations. Costs list shows raw API estimate/final and converted company amount. No callback receiver, official label, official monthly statement, automatic return order or token exchange. API key as Bearer needs sandbox verification. No live Odoo installation performed. Do not install over earlier incompatible versions without backup and migration review. Test only. Network failures mark pending; reconcile by trace before any retry. A process crash or DB rollback can still lose local attempt state; check remote orders before resubmitting. Carrier configuration and parcel fields are intended for trusted inventory staff; production hardening needed.
